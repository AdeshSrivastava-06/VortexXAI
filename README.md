# MoES BUST-DETECT

## Operational NCMRWF NWP Forecast Bust Prediction & Uncertainty Mapping System

## Project Overview

The system produces a continuous bust-risk probability for Indian land grid points and supports click-to-explain analysis for individual locations.

## Key Capabilities & Deliverables

| System Capability | Implementation in VortexXAI | 
| :--- | :--- | :--- |
| **Forecast Confidence Map** | 3D MapLibre/deck.gl grid visualization showing regional confidence/risk scores across India. | 
| **Forecast Bust Probability** | Stacking ensemble calculates continuous probability percentages (0%–100%) for forecast failure. |
| **Error-Prone Area Detection** | Automated ranking of top high-risk failure zones (e.g., Western Ghats, Gangetic Plains). | 
| **Explainable Output (XAI)** | Real-time SHAP feature impact analysis and LIME local surrogate weights for key drivers. | 
| **Prototype Dashboard & API** | Full FastAPI backend with POST endpoints paired with a React + Vite operational interface. | 

### Machine-learning pipeline

1. **Spatio-temporal model:** A PyTorch ConvLSTM processes five time steps of four-channel spatial weather tensors.
2. **Tabular models:** LightGBM and CatBoost model non-linear interactions among temperature anomaly, rain acceleration, wind shear, humidity, and pressure drop.
3. **Meta-learner:** A stacking logistic-regression layer combines the ConvLSTM, LightGBM, and CatBoost probabilities.
4. **XAI layer:** SHAP feature impacts and LIME local surrogate weights provide operational explanations for each prediction.

The ConvLSTM captures spatial wave dynamics and continuity across adjacent grid cells, while LightGBM and CatBoost model local thermodynamic feature interactions.

### Ground-truth error metric

The intended bust target is generated by comparing forecast and observed fields dynamically:

$$\text{Bust} = 1 \quad \text{when} \quad (\Delta\text{Rain} > 25\text{ mm}) \quad \text{OR} \quad (\Delta\text{Temperature} > 3.0^\circ\text{C})$$

In the current checked-in inference build, the backend consumes the local ERA5-style NetCDF artifact and deterministic weather-generation inputs for the API feature stream. Training-data and observation-ingestion jobs are not included in this repository.

## Key Features

- Continuous 0–100% Forecast Bust Risk Probability alongside complementary Forecast Confidence Scores (Confidence = 100% - Bust Risk) per grid cell.
- Automatic identification and ranking of high-risk zones, including coastal regions and the Western Ghats.
- SHAP and LIME explanations for Wind Shear, Temperature Anomaly, Rain Acceleration, Pressure Drop, and Humidity.
- Interactive Day 1-Day 10 lead-time evaluation.
- ConvLSTM spatial processing from a local NetCDF weather tensor.
- FastAPI prediction and click-to-explain endpoints.
- React, MapLibre/deck.gl, and Tailwind-based operational visualization.

## Architecture

```text
Frontend (React + Vite + MapLibre/deck.gl)
        |
        | POST /api/predict and /api/explain_point
        v
FastAPI backend
        |
        +--> ConvLSTM <-- 5 x 4-channel spatial crop from ERA5 NetCDF
        +--> LightGBM <-- 5-feature tabular matrix
        +--> CatBoost <-- 5-feature tabular matrix
        +--> Logistic-regression meta-learner
        +--> SHAP + LIME explanations
```

## Installation

### Prerequisites

- Python 3.11 or newer
- Node.js 18 or newer and npm
- Git
- Sufficient memory for PyTorch and the spatial NetCDF dataset

### 1. Clone the repository

```bash
git clone https://github.com/AdeshSrivastava-06/VortexXAI.git
cd VortexXAI
```

### 2. Create the Python environment

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r backend\requirements.txt
```

Linux or macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r backend/requirements.txt
```

### 3. Install frontend dependencies

```bash
cd frontend
npm install
cd ..
```

## Quick Start

### Start the API

From the repository root:

```bash
cd backend
python -m uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

The API will be available at `http://localhost:8000`.

### Start the dashboard

In a second terminal:

```bash
cd frontend
npm run dev
```

Open the Vite URL shown in the terminal, normally `http://localhost:5173`.

### API endpoints

#### `POST /api/predict`

Request:

```json
{
  "lead_day": 3
}
```

Returns the risk-scored Indian grid and model-derived driver fields.

#### `POST /api/explain_point`

Request:

```json
{
  "lat": 15.5,
  "lon": 73.83,
  "lead_day": 3
}
```

Returns the point prediction, SHAP values, LIME weights, feature values, and a dynamic operational insight.

## Data and Reproducibility Notes

- The checked-in `.pth`, `.txt`, `.cbm`, `.npy`, and `.nc` artifacts are required by the current local inference path and are intentionally versioned.
- If the NetCDF file is unavailable, the backend can create a regional synthetic NetCDF dataset and has a deterministic random tensor fallback for failed spatial crops. That fallback is intended for development resilience, not scientific validation.
- The current API weather feature generator is deterministic for a coordinate and lead day. Replace it with an authenticated forecast/observation ingestion service before production deployment.
- Do not commit credentials, API tokens, private observation data, or local environment files.
